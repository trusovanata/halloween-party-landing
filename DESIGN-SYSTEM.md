**Правило:** шрифт в vw при `nowrap` проверять измерением: если строка не влезает в контейнер (ширина экрана минус отступы), уменьшать vw, а не разрешать перенос. («GONE DARK» при 17vw был 357px на 375px экране при доступных 327px.)

### 2.4 Отступы и ритм

- **Боковые поля (`--side`)**: 24px на мобильном, 48px на планшете, `6.25vw` на десктопе (`1680px` контента и `120px` поля от 1920px).
- **Контент**: `--content: min(87.5vw, 1680px)`; от 1920px страница центрируется (`.site-shell { max-width: 1920px }`).
- **Высота шапки**: 76px на мобильном и планшете, `5.677vw` на десктопе. `.site-shell` и `html { scroll-padding-top }` повторяют это значение, держать три места согласованными.
- **Вертикальный зазор между секциями на мобильном: 64px** (токен дизайн-системы `--space-section-y = clamp(4rem, 8vw, 10rem)`, 4rem). Из него складывается: нижний padding hero 64px + `.magic` без своего верхнего padding.
- Блоки раньше имели «чёрные провалы» из-за фиксированных `min-height`. Правило: высоту секции задаёт контент и токен зазора, а не `min-height` в пикселях.

## 3. Брейкпоинты и логика раскладки

Mobile-first: базовые правила — мобильные, дальше переопределения.

| Диапазон | Раскладка |
|---|---|
| `< 768px` | колонка, блок `@media (max-width: 767px)` с мобильными доводками |
| `768–1199px` | планшет: сетка у `.magic`, свои размеры шрифтов, нет абсолютного позиционирования |
| `≥ 1200px` | **постерная раскладка 1920×…**: почти всё `position: absolute` с координатами в `vw` |
| `≥ 1920px` | `--content: 1680px`, `--side: 120px`, шапка центрируется формулой `max(0px, (100vw - 1920px)/2)` |

Правила:

1. На десктопе координаты — `vw`, не `px`, чтобы композиция масштабировалась как макет 1920. Числа сохранены от Figma (`top: 13.177vw` и т.п.).
2. Правило, добавленное для мобильного, **обязательно проверять на ≥1200px** и в `768–1199px`. Если десктопный блок переопределяет `position`, он должен сбросить `right`, `bottom`, `z-index`, `max-width`, `max-height`, `transform` базового правила. (Случаи: кнопка hero тянулась на 195px из-за `bottom:16px`; полароид сжимался из-за `max-height:160px`; `.dance__title` растягивался из-за `right:24px`.)
3. Селекторы вида `.hero__title span` ловят **все вложенные** `span`, включая обёртки анимации. Использовать `.hero__title > span`.
4. Всякий фикс проверять минимум на ширинах 375, 412 (реальный телефон ≈ 412×735 с адресной строкой), 1000 (планшет), 1440 и 1920.

## 4. Компоненты

### 4.1 Шапка `.header`
`position: fixed` на всю ширину, высота 76px (`5.677vw` на десктопе), матовое стекло. Отступы контента — через `padding`, а не через уменьшение ширины: стекло идёт от края до края. Ссылки: When (`#when`), Dress Code (`#dress-code`), Where (`#where`), справа маленькая кнопка «Claim your seat». На мобильном меню скрыто.

Якоря: `html { scroll-padding-top }` = высота шапки; на десктопе `#dress-code { scroll-margin-top: -32vw }` (секция начинается с фото паука на ~58vw, текст ниже), `#where { scroll-margin-top: 3vw }`.

### 4.2 Hero
Порядок: eyebrow → видео-тыква → мета (`.hero__meta`: дата · место · город **в одну строку** с точками-разделителями на мобильном; на десктопе три отдельных позиции) → «A BIRTHDAY / GONE DARK» → кнопка.
- Мобильный: высота по контенту, заголовок обязан помещаться над фиксированной кнопкой (проверено: зазор 46px на 412×735, 23px на 375×667). Пустые поля вокруг тыквы выбираются отрицательным `margin-bottom` у `.hero__video-frame`.
- Десктоп: тыква поверх «GONE DARK» (`z-index: 8`), под ней синее пятно `.hero__glow` (`130vw × 96vw`, мягкое, правее и ниже центра).
- Тыква: `pumpkin-loop-alpha.webm` (VP9 с **настоящей** альфой, вырезано вручную в After Effects, Roto Brush) первым `<source>`, `pumpkin-loop.mp4` запасным. Никаких `mask-image`/`mix-blend-mode` на видео. Пока видео не играет, у кадра мягкое оранжевое свечение (`.hero__pumpkin-motion--loading`).

### 4.3 CTA «Claim your seat»
- **Мобильный/планшет (<1200)**: `position: fixed`, снизу по центру (`left/right: 16px`, `max-width: 360px`), виден наверху страницы и пока низ hero не поднялся в зону кнопки (~96px от низа экрана), дальше скрывается (класс `is-hero-hidden`, `opacity:0 !important` нужен, потому что motion сам пишет `opacity`/`transform` в `style`). Состояние `heroInView` считает обработчик скролла в `App`.
- **Десктоп**: обычная абсолютная кнопка в композиции (`top 41vw`, `left 43.5vw`, `width 13vw`).
- Почему не `position: sticky`: у `.site-shell` стоит `overflow: hidden`, а любой предок с `overflow != visible` ломает `sticky`.

### 4.4 Переключатель звука
Круглая «таблетка» справа внизу (`fixed`, z 30). Пока виден hero на мобильном/планшете, живёт справа под строкой eyebrow (`top: 134px`), чтобы не закрывать подпись и заголовок. Фоновая музыка `hellowin-theme` (opus + mp3), громкость 0.32; ролик с ведьмами и тыква без звука.

### 4.5 Фото и подложки
- Фото-блоки обрамлены растушёвками `.fade` (сверху и снизу, градиент в `#000`), чтобы секции не резались прямым краем.
- **Полароид** (`.spider__small`): рамка `#f3ede2`, нижний край толще, тень; `padding` в px на мобильном и в vw на десктопе; картинка внутри должна оставаться **квадратной** (исходник 1024×1024): никаких ограничений `max-height`, которые её сплющат.
- `.spider__media` на мобильном 430px высотой (исходник широкий 1344×768, при большей высоте `object-fit: cover` зумит и растягивает паука).
- На десктопе фото паука **перевёрнуто по вертикали** (`scaleY(-1)`), камера внизу; на мобильном камера сверху. Любой слой, привязанный к фото (вспышка), обязан переворачиваться вместе с ним.
- Секция «Dance more»: «DANCE MORE» лежит **поверх нижней тёмной части фото**, по центру, и на мобильном (`top: 692px`), и на десктопе (`top: 65.469vw`).

### 4.6 Форма RSVP, счётчик, карта, футер, бегущая строка
- Форма: имя + «Bringing anyone?»; пока без бэкенда (решено делать через Google Forms/Sheets, ждём ссылку).
- Счётчик до 31 октября 17:00 (`+02:00`), обновляется раз в секунду.
- Футер: «Halloween · Julia» / «October 31 · 17:00» двумя группами `nowrap`, перенос только между ними.
- Бегущая строка: красная полоса высотой 52px, строка `DANCE MORE · DRESS TO KILL · OCTOBER 31 · 17:00`.

## 5. Движение

Принципы: анимация объясняет сюжет («картинка выезжает», «камера щёлкает»), всё срабатывает **один раз при появлении в кадре** (кроме дыма), всё уважает `prefers-reduced-motion` (без анимации контент просто показан).

Общие константы: `REVEAL_EASE = [0.22, 1, 0.36, 1]`; появление `0.7–0.9s`; появление букв `0.06s` между буквами.

| Что | Как |
|---|---|
| Hero | `heroStagger` + `revealItem` (opacity + y16), «GONE DARK» собирается по буквам (`SplitLetters`, задержка 0.7s) |
| «DANCE MORE» | те же `SplitLetters`, без пружины и отскока (так же, как «GONE DARK») |
| Заголовки секций | `slideIn("left"/"right")`, дрейф ±90px, чередование сторон |
| Фото тыквы и ведьм в «One night» | тыква справа, ведьмы слева (`x ±140`), поворот держится через `style.rotate` |
| Вспышка паука | триггер: середина фото паука в средней трети экрана (датчик `.spider__trigger`); через 0.8s вспышка на камере, через 1.2s полароид падает и «проявляется» (`brightness 2.6 → 1`, `saturate .2 → 1`) |
| Дым тыквы | две конусные струи в стороны от пасти, SVG-фильтр `feTurbulence` + `feDisplacementMap`; бесконечный цикл; не на ведьм |
| Маркиза, значок-кольцо | бесконечные CSS-анимации; при reduced motion отключаются |

Правила:
1. Слой-эффект поверх картинки с `object-fit: cover` считать **в координатах картинки**: слой шириной `max(100%, 100cqh * W/H)` с `aspect-ratio` картинки (на контейнере `container-type: size`), процентные позиции — это точки самого фото. Камера паука: `(36.2%, 24.3%)`; пасть тыквы: `(51.3%, 41%)`.
2. Не анимировать `transform` на элементе, у которого `transform` задан в CSS: motion перезапишет его. Поворот и масштаб такого элемента задавать через `style={{ rotate }}`.
3. Разбиение на буквы убивает кернинг: у каждой буквы `margin-right: -0.0145em`, иначе строка шире и вылезает за край. Слова — `nowrap`-блоки, `aria-label` держит текст читаемым.
4. Яркие вспышки: одна, короткая, только один раз, и без неё при reduced motion.
5. Эффект должен срабатывать, когда зритель дошёл до блока глазами, а не когда он показался с края экрана.

Как делать видео с прозрачностью: вырезать контур вручную (After Effects Roto Brush) или платным сервисом, экспорт ProRes 4444 с альфой, затем `ffmpeg -vf "format=yuva420p" -c:v libvpx-vp9 -pix_fmt yuva420p -b:v 2200k -auto-alt-ref 0 -an out.webm`. Простое вырезание по цвету/яркости не подходит, когда цвет объекта совпадает с фоном (проверено на тыкве). Проверять результат только реальным рендером `<video>` в браузере на цветном фоне, а не `ffprobe`.

Видео обязательно отдавать вторым `<source>` в mp4 как запасное и держать размер файлов небольшим.

## 8. Работа и деплой

```bash
# проверка локально
npx vite --port 5190 --strictPort

# сборка и деплой (основной адрес обновляется за несколько секунд)
npx vite build
npx wrangler pages deploy dist --project-name=halloween-party-landing --branch=main --commit-dirty=true

# в GitHub (должен быть залогинен trusovanata: gh auth switch --user trusovanata)
git add <файлы> && git commit -m "..." && git push origin main
```

Если после деплоя не видно изменений: подождать несколько секунд и обновить страницу (`Ctrl+Shift+R`).

Правила работы:
1. Не пушить из Figma Make. Не делать `force push`.
2. Кредиты Figma/Lovable только на генерацию интерфейса; документы, токены и правки кода идут через git.
3. Пароли, личные почты и токены не попадают ни в код, ни в видео, ни в посты.
